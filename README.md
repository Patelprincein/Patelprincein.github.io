# Prince Patel · Experiments Portfolio

Everything lives in `portfolio/` and ships as a high-end React + Vite experience for [@PatelPrinceIn](https://github.com/PatelPrinceIn). It features glassmorphism hero art, floating nav, data-driven sections, MDX writing, GitHub API cards, and a radar-chart skills view.

## Highlights
- ⚡ **React 18 + TypeScript + Vite 7** with MDX hydration and Framer Motion animations.
- 🌗 **Persistent theme toggle** (system-aware) with cursor glow, parallax shapes, and auto-hiding nav.
- 🧠 **Single config** (`src/config/siteConfig.ts`) controls hero copy, skills, projects, socials, learning card, experience, and SEO metadata.
- 📰 **MDX blog system** (`src/content/posts/*.mdx`) with reading-time extraction, live preview panel, and tag pills.
- 🛰️ **GitHub pinned feed** (`useGithubPinnedRepos`) hits the public pinned API with graceful fallback to local data.
- 📈 **Skills radar chart** (Recharts) + motion reveal utilities and 3D tilt cards.
- 🗺️ **Meta + SEO ready**: JSON-LD, share image, favicon + touch icon, sitemap/robots/autogenerated `public/site.webmanifest`, and analytics placeholder.

## Local Development
```powershell
# install deps
npm install

# start dev server
npm run dev
```
Vite prints a local URL like `http://localhost:5173`. Hot module replacement covers MDX, config changes, and CSS.

### Customizing Content
1. **Global config**: edit `src/config/siteConfig.ts` to change hero text, marquee words, skill groups, learning focus, featured/gallery projects, experience bullets, contact info, analytics settings, etc.
2. **Projects/GitHub feed**: add to `siteConfig.projects` or rely on real pinned repos. The GitHub component automatically falls back when the API rate-limits.
3. **Blog posts**: duplicate one of the `src/content/posts/*.mdx` files, update the exported `frontmatter`, and add MDX content. The reader instantly picks it up.
4. **Styles**: tweak design tokens inside `src/styles/tokens.css` or extend utilities in `src/styles/global.css`.
5. **Imagery**: replace `/public/assets/profile-placeholder.svg` and blog placeholder art with real images (same filenames to avoid path changes).

## Production Build & Preview
```powershell
npm run build   # runs sitemap generation, type-checks, and Vite build
npm run preview # optional local preview of dist/
```
The build emits `/dist` along with warnings if bundle chunks exceed 500 kB (expected due to Recharts + MDX). Reading-time relies on `reading-time`, so Vite logs that Node "stream" is polyfilled — safe to ignore.

## Deployment · GitHub Pages (`PatelPrinceIn`)
1. **Create repo** (recommended name: `portfolio` or `PatelPrinceIn.github.io`).
2. **Initialize + push source**
   ```powershell
   cd portfolio
   git init
   git add .
   git commit -m "Initial portfolio site"
   git branch -M main
   git remote add origin https://github.com/PatelPrinceIn/<repo-name>.git
   git push -u origin main
   ```
3. **Build static output**
   ```powershell
   npm run build
   ```
4. **Publish `dist/`**
   - If the repo is `PatelPrinceIn.github.io`, copy the contents of `dist/` into the repo root and push to `main`.
   - For any other repo (e.g., `portfolio`), push `dist/` to a dedicated `gh-pages` branch:
     ```powershell
     git subtree push --prefix dist origin gh-pages
     ```
     or use the [`gh-pages`](https://www.npmjs.com/package/gh-pages) CLI / GitHub Action to automate.
5. **GitHub Pages settings**
   - Settings → Pages → Build & deployment
   - Source: `Deploy from a branch`
   - Branch: choose `gh-pages` (or `main` with `/docs` if you moved `dist` into `/docs`).
   - Save and wait for Pages to deploy.
6. **Set Vite base path**
   - When hosting at `https://PatelPrinceIn.github.io/<repo>/`, open `vite.config.ts` and set `base: '/<repo>/'`.
   - Re-run `npm run build` and republish `dist/`.
7. **Automation tip**: keep `npm run sitemap` (already part of the build script) so new sections are auto-listed.

## Troubleshooting
- **Chunk size warnings**: Vite will warn about bundle size because of Recharts and MDX. Use dynamic imports or tweak `build.chunkSizeWarningLimit` if necessary.
- **Pinned repo errors**: If the pinned API rate-limits, the component falls back to local project data and surfaces a muted error line. Nothing breaks.
- **MDX imports**: When adding new posts ensure they export `frontmatter` (see existing files) so `blogPosts` can compute metadata.
- **Theme flash**: The theme provider reads from `localStorage`; if you test in SSR contexts, guard window access accordingly.
